# Phase 01.1: Shock counter, chart image export, and glossary tooltip JS — Research

**Researched:** 2026-04-15
**Domain:** Static dashboard redesign on Observable Framework — dark-theme card grid, Tailwind integration, JS-animated shock counter, per-chart PNG export, vanilla-JS glossary tooltip
**Confidence:** HIGH for stack identification (energydashboard.co.uk reverse-engineered to ApexCharts; Tailwind v4 + Framework integration paths verified from upstream issue thread; existing pipeline modules read directly); MEDIUM for exact dark palette values (treated as design targets in UI-SPEC, executor-confirmable on implementation day); MEDIUM for £/sec rolling window (a defensible default proposed, not benchmarked against UI feel)

---

## Summary

Phase 01.1 absorbs three "small" deliverables (shock counter, chart PNG export, glossary tooltip) into a full visual redesign of the public site. The stack pivots: **Pico CSS out, Tailwind in; light theme out, dark theme in; Observable Plot remains the chart engine** (ApexCharts is what the reference site uses, but the cost of swapping libraries is not justified — Plot can hit the dark aesthetic with token swaps and the existing scissors page is already wired to it). The hero shock counter is computed at build time from `SUM(CFD_Payments_GBP)` for the current calendar year, with a constant £/sec rate derived from the trailing 30-day mean daily subsidy. The PNG export pipeline is an extension of `pipeline/build_og_image.py` rebound to dark backgrounds. The glossary tooltip is ~80 lines of vanilla JS loaded as a single ES module on every page.

The biggest unknown going in — **what charting library does energydashboard.co.uk use?** — is now answered: **ApexCharts** (confirmed by string match in `_next/static/chunks/967-dac8c164da90cebd.js`). The recommendation is nevertheless to **stay on Observable Plot** for Phase 01.1 because (a) the existing CHART-01 wiring works, (b) Plot ships zero-cost inside Framework, (c) the visual style of dark backgrounds + saturated lines + area fill is well within Plot's range, and (d) ApexCharts adds 9 MB unpacked + a non-MIT licence (`SEE LICENSE IN LICENSE` — not OSI standard) for visual parity that the user asked for in *aesthetic*, not *implementation*.

The biggest planning-time risk is **Tailwind ↔ Framework integration**. There is no first-class integration; the upstream issue (#595) is a 2-year-old enhancement request. Two viable paths exist (CDN browser build, CLI-driven build step) — see Open Questions Q1.

**Primary recommendation:** Use **Tailwind v4 standalone CLI** as a pre-build step that emits `src/assets/tailwind.css`, registered in `observablehq.config.js` `head`. Keep Observable Plot as the chart engine with dark-themed token overrides. Build the shock counter as `requestAnimationFrame`-driven vanilla JS reading `meta.json.gbp_per_sec_rate`. Generate per-chart PNGs by extending `pipeline/build_og_image.py` into a multi-target `pipeline/export_chart_images.py`. Implement the glossary tooltip as a single `src/components/glossary-tooltip.js` module imported by every page.

### Pattern 1: Tailwind v4 standalone CLI integrated with Observable Framework

**What:** Compile Tailwind once before `observable build`, output to `src/assets/tailwind.css`, register in Framework `head`.

**When to use:** This is the recommended path for Phase 01.1 — survives into Phase 02 with no rework, ships nothing to client beyond the minified CSS file.

**Why not the alternatives:**
- **Tailwind Play CDN (`@tailwindcss/browser@4`):** Works `[VERIFIED: confirmed in observablehq/framework#595 comments by user daniel-payne]` but adds runtime JS overhead and parses HTML in the browser to derive utilities. Acceptable for prototyping only.
- **PostCSS plugin chain (`@tailwindcss/postcss`):** Requires wiring into Framework's esbuild-driven asset pipeline, which has no documented extension hook. The upstream `esbuild-plugin-tailwindcss` route is mentioned in framework#595 comments but does not solve the preflight-vs-Markdown reset issue.

**Example — `package.json` scripts:**

```json
{
  "scripts": {
    "css:build":  "tailwindcss -i src/styles/app.css -o src/assets/tailwind.css --minify",
    "css:watch":  "tailwindcss -i src/styles/app.css -o src/assets/tailwind.css --watch",
    "build":      "npm run css:build && observable build",
    "dev":        "npm-run-all --parallel css:watch observable:dev",
    "observable:dev": "observable preview"
  },
  "devDependencies": {
    "tailwindcss":          "4.2.2",
```

### Pattern 2: Shock counter — `requestAnimationFrame` ticker

**What:** Vanilla JS reads start value + £/sec rate from DOM data attributes, animates a span with `requestAnimationFrame`.

**Example:**

```html
<!-- in src/index.md -->
<section class="bg-card py-12 text-center">
  <p class="text-base text-muted">Total CfD subsidy paid since 1 Jan ${meta.ytd_label_year}</p>
  <p class="text-shock text-accent"
     id="shock-numeral"
     data-start="${meta.ytd_subsidy_gbp}"
     data-rate="${meta.gbp_per_sec_rate}">
    £${(meta.ytd_subsidy_gbp / 1e9).toFixed(2)} billion
  </p>
  <p class="text-sm text-muted">As of ${meta.ytd_as_of}</p>
</section>

<script type="module">
  const el = document.getElementById("shock-numeral");
  const start = parseFloat(el.dataset.start);
  const rate  = parseFloat(el.dataset.rate);  // £/sec

  const reduceMotion = window.matchMedia("(prefers-reduced-motion: reduce)").matches;
  if (reduceMotion || !rate) {
    // Freeze at build-time value; do not start loop
  } else {
    const t0 = performance.now();
    const fmt = new Intl.NumberFormat("en-GB", {
      minimumFractionDigits: 2, maximumFractionDigits: 2
    });
    function tick(now) {
      const elapsedSec = (now - t0) / 1000;
      const value = start + elapsedSec * rate;
      el.textContent = "£" + fmt.format(value / 1e9) + " billion";
      requestAnimationFrame(tick);
    }
    requestAnimationFrame(tick);
  }
</script>
```

Notes:
- `aria-live="off"` (default) — the ticking is decorative noise; AT consumes the static label + as-of stamp.
- `Intl.NumberFormat("en-GB")` provides the comma thousands separator; the billion divisor is applied at format time so the underlying counter remains in £ for precision.
- `tabular-nums` font-feature-setting (in `.text-shock`) prevents horizontal jitter as digits change.

```js
const HOVER_DELAY_MS   = 150;
const DISMISS_DELAY_MS = 100;
const reduceMotion = matchMedia("(prefers-reduced-motion: reduce)").matches;

let glossary = null;
let activeTooltip = null;
let hoverTimer = null;
let dismissTimer = null;

async function loadGlossary() {
  if (glossary) return glossary;
  const res = await fetch("/content/glossary.json");
  glossary = await res.json();
  return glossary;
}

function buildTooltip(slug, entry) {
  const tip = document.createElement("div");
  tip.id = `tooltip-${slug}`;
  tip.setAttribute("role", "tooltip");
  tip.className = [
    "fixed bg-card border border-surface rounded p-2 px-3 shadow-lg",
    "max-w-[280px] text-sm z-[100]",
    reduceMotion ? "" : "transition-opacity duration-[120ms] opacity-0"
  ].join(" ");
  tip.innerHTML = `
    <strong class="text-primary font-semibold block">${entry.term}</strong>
    <span class="text-muted block">${entry.definition}</span>
    ${matchMedia("(hover: hover)").matches
      ? '<span class="text-muted text-sm block mt-1">(press Esc to close)</span>'
      : ''}
  `;
  document.body.appendChild(tip);
  return tip;
}

function position(tip, anchor) {
  const r = anchor.getBoundingClientRect();
  const tr = tip.getBoundingClientRect();
  let top = r.top - tr.height - 8;
  if (top < 8) top = r.bottom + 8;          // flip below if above viewport
  let left = r.left + (r.width - tr.width) / 2;
  left = Math.max(8, Math.min(left, innerWidth - tr.width - 8));
  tip.style.top = `${top}px`;
  tip.style.left = `${left}px`;
}

function show(anchor) {
  const slug = anchor.dataset.glossary;
  const entry = glossary[slug];
  if (!entry) return;
  hide();  // dismiss any active
  const tip = buildTooltip(slug, entry);
  position(tip, anchor);
  anchor.setAttribute("aria-describedby", tip.id);
  activeTooltip = { tip, anchor };
  if (!reduceMotion) requestAnimationFrame(() => tip.style.opacity = "1");
}

function hide() {
  if (!activeTooltip) return;
  const { tip, anchor } = activeTooltip;
  anchor.removeAttribute("aria-describedby");
  tip.remove();
  activeTooltip = null;
}

async function init() {
  await loadGlossary();
  const anchors = document.querySelectorAll("abbr[data-glossary]");
  for (const a of anchors) {
    a.tabIndex = 0;
    a.addEventListener("mouseenter", () => {
      clearTimeout(dismissTimer);
      hoverTimer = setTimeout(() => show(a), HOVER_DELAY_MS);
    });
    a.addEventListener("mouseleave", () => {
      clearTimeout(hoverTimer);
      dismissTimer = setTimeout(hide, DISMISS_DELAY_MS);
    });
    a.addEventListener("touchstart", (e) => {
      e.preventDefault();
      activeTooltip?.anchor === a ? hide() : show(a);
    }, { passive: false });
    a.addEventListener("keydown", (e) => {
      if (e.key === "Enter" || e.key === " ") { e.preventDefault(); show(a); }
    });
  }
  document.addEventListener("keydown", (e) => { if (e.key === "Escape") hide(); });
  document.addEventListener("touchstart", (e) => {
    if (activeTooltip && !activeTooltip.tip.contains(e.target) && e.target !== activeTooltip.anchor) hide();
  });
  window.addEventListener("scroll", hide, { passive: true });
}

if (document.readyState === "loading") {
  document.addEventListener("DOMContentLoaded", init);
} else {
  init();
}
```

Notes:
- Tooltip element is `position: fixed` and appended to `document.body` to escape any chart `overflow: hidden` containers.

### Anti-Patterns to Avoid

- **Computing the £/sec rate in the browser.** The pipeline emits a single float; the client only adds elapsed time. Never trust the client to compute the rate from an array of daily figures — wastes bandwidth and recomputes per visit.
- **Updating the shock counter via `setInterval(..., 1000)`.** A 1Hz tick produces visible "jumps" of £X every second, which looks fake at typical UK CfD spend rates. Use `requestAnimationFrame` for smooth sub-pixel updates.
- **Generating PNGs via headless browser (Puppeteer/Playwright).** matplotlib already works, has no Chrome dependency, and runs in seconds. Headless-browser image gen would inflate CI minutes and add a Chromium dep.
- **Wiring the Tailwind PostCSS plugin into Framework's esbuild.** Framework offers no documented esbuild extension hook; community attempts (per framework#595 comments) hit the preflight-vs-Markdown reset issue. Standalone CLI sidesteps this entirely.
- **Adding `<abbr data-glossary>` to chart axis tick labels.** Tick labels are SVG `<text>` elements rendered by Plot — `<abbr>` semantics don't apply. D-20 makes this explicit.
- **Storing `tailwind.css` in source control.** It's a build artefact; commit `src/styles/app.css` (input), gitignore `src/assets/tailwind.css` (output). Build it in CI before `observable build`. Exception: if Cloudflare Pages deploys from a non-CI source, commit it.
- **Using AI-generated placeholder PNG visuals.** matplotlib drawing a literal "Chart coming in Phase 02" panel is faster, deterministic, and has no licensing risk.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Number formatting (`£3,471,000,000` → `£3.47 billion`) | Custom string-split + commas | `Intl.NumberFormat("en-GB", { ... })` | Locale-correct, zero deps, handles negatives, fixed precision, builtin in every modern browser |
| Animation loop | `setInterval` + manual delta tracking | `requestAnimationFrame` + `performance.now()` | Browser pauses rAF in background tabs (saves CPU), syncs to display refresh, smooth at any framerate |
| Reduced-motion detection | UA sniff or hand-rolled toggle | `matchMedia("(prefers-reduced-motion: reduce)").matches` | OS-honest accessibility signal |
| Tooltip positioning (anchor + flip) | Custom math chasing viewport edges | Same simple bounding-box math (in glossary-tooltip.js Pattern 3) — but DON'T pull in `@floating-ui/dom` for this scope | A 7-line position function suffices for ~30 tooltip targets across 5 pages; floating-ui is overkill until popovers acquire arrow indicators or collision strategies |

## Common Pitfalls

### Pitfall 1: Tailwind preflight breaks Framework Markdown rendering

**What goes wrong:** Tailwind v4's preflight zeroes out paragraph margins, list bullets, heading sizes. Framework Markdown pages then look like an unstyled wall of text.

**Why it happens:** Tailwind targets component-built apps where the developer reapplies utilities; Framework writes prose-shaped HTML that depends on default user-agent styles.

**How to avoid:**
- Add a small `prose` reset in `src/styles/app.css` (see Pattern 1 example) — re-establish `p`, `h1`, `h2`, `h3`, `ul`, `li` rhythm.
- Apply `class="prose"` to the main content wrapper of editorial sections; leave the card grid and chart figures unwrapped (utility-driven).
- Confirmed pitfall in upstream `observablehq/framework#596` thread.

**Warning signs:** `index.md` renders with paragraphs jammed together; chart titles inherit body weight.

### Pitfall 2: `gbp_per_sec_rate` becomes meaningless when subsidy goes negative

**What goes wrong:** `CFD_Payments_GBP` is **signed** (negative during 2022 clawback) `[VERIFIED: pipeline/schema.py line 9 + line 82]`. A rolling-mean window that straddles a clawback period yields a negative or near-zero rate. UI shows a counter that ticks *down* or freezes.

**Why it happens:** The "shock counter" framing assumes a positive monotonically-increasing cost. The data structure permits net-negative months.

**How to avoid:**
- Use **trailing 30 days excluding clawback months** (i.e., filter `WHERE CFD_Payments_GBP > 0` for the rate window) OR use `GREATEST(rate, 0)` clamp.
- Document the clamp in the boxout: "Average daily subsidy is computed from the most recent positive-subsidy days only."
- Recommended SQL (in `build_meta.py`):
  ```sql
  WITH daily AS (
    SELECT Settlement_Date AS d, SUM(CFD_Payments_GBP) AS daily_gbp
    FROM raw_generation
    WHERE Settlement_Date > (SELECT MAX(Settlement_Date) FROM raw_generation) - INTERVAL 30 DAY
    GROUP BY 1
  )
  SELECT GREATEST(AVG(daily_gbp) / 86400.0, 0.0) AS gbp_per_sec_rate FROM daily;
  ```

**Warning signs:** Counter visibly ticks downward in browser; QA runs after a clawback-month window report rate near zero.

### Pitfall 3: YTD `as_of` confused with build date

**What goes wrong:** Pipeline build date and dataset `max_settlement_date` are NOT the same (LCCC has multi-day publishing lag). Showing "As of {build date}" overstates currency.

**How to avoid:** `ytd_as_of` MUST be `meta.max_settlement_date` (the date in the data), NOT `meta.last_updated` (the time the pipeline ran).

**Warning signs:** Site claims "As of 2026-04-15" while underlying data ends 2026-04-12.

### Pitfall 4: `Settlement_Date >= '<year>-01-01'` and timezones

**What goes wrong:** PIPE-08 establishes UTC-naive date semantics. If anyone introduces `datetime.now()` in UK Summer Time (BST) at midnight on Jan 1, the pipeline could compute YTD against the wrong year boundary.

**How to avoid:** Compute `ytd_label_year` as `extract(year from max(Settlement_Date))` from the dataset itself, not `datetime.now().year`. The data is the source of truth.

### Pitfall 5: Per-chart PNG build runs even when data is stale

**What goes wrong:** D-16 says image regen must skip when schema validation fails. If `export_chart_images.py` is invoked unconditionally, it overwrites yesterday's good PNG with today's stale-data PNG.

**How to avoid:** The `pipeline/__main__.py` early-return on `EXIT_SCHEMA_DRIFT` (line 78 in current code) already enforces this — `export_chart_images` runs only after step 2 passes. Verify the new step is wired AFTER the schema validation step, not before.

**Warning signs:** Identical PNGs but updated `meta.json` would indicate the gate is correctly working; differing PNGs but unchanged `meta.last_updated` would indicate broken.

### Pitfall 6: Tailwind output not in the build artefact

**What goes wrong:** `src/assets/tailwind.css` is built by the CLI but is not picked up by `observable build` because the user forgot to run `npm run css:build` first. CI deploys a site referencing a 404'd stylesheet.

**How to avoid:** `package.json`'s `build` script chains `css:build && observable build` (see Pattern 1 example). Never run `observable build` directly in CI; always go through `npm run build`.

### Pitfall 7: Inter font FOUT on slow connections

**What goes wrong:** Google Fonts `<link>` blocks-then-paints; on slow networks, shock counter renders briefly in fallback sans-serif, then jumps to Inter — visible layout shift.

**How to avoid:** `font-display: swap` is set by default in Google Fonts URLs. Apply `font-variant-numeric: tabular-nums` to **both** Inter and the fallback stack so digit widths match closely. Alternatively, self-host Inter and serve with `<link rel="preload">`.
