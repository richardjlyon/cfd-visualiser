# Phase 01.1: Shock counter, chart image export, and glossary tooltip JS — Context

**Gathered:** 2026-04-15
**Status:** Ready for planning

> **Scope note:** The inserted phase title under-describes the work. This phase absorbs a full visual redesign of the site, driven by the user's decision that the existing Phase 01 design is proof-of-concept only. The three original items (shock counter, chart image export, glossary tooltip JS) now ship inside the new design. The original 01-UI-SPEC.md is **superseded** for landing and detail pages — a new UI design contract will be generated in this phase via `/gsd-ui-phase 01.1`.

<domain>
## Phase Boundary

Deliver a redesigned public-facing site for the CfD Visualiser that:

1. **Matches the look & feel of https://www.energydashboard.co.uk/live** — palette, typography, chart visual language, card/grid layout pattern.
2. **Landing page = card grid** of the 4 v1 charts from `docs/visualisation-scope.md`, each card clicking through to its own detail page.
3. **Scissors (CHART-01) is the only fully-wired chart** — its detail page carries the existing editorial context (provocative title, caption, description, source citation, "What does this mean?" boxout, Download JSON, Download Image PNG, glossary tooltips).
4. **Three placeholder detail pages** (CHART-02, CHART-03, CHART-04) with real editorial scaffolding but dummy/placeholder chart bodies.
5. **Hero shock counter** on the landing page: today's YTD cumulative consumer subsidy, rendered at build time, with a JS **count-up effect that starts at today's value and continuously increments upward** at a constant £/sec rate derived from recent historical daily subsidy.
6. **Per-chart PNG download** (one PNG per detail page; scissors the only real render; placeholders for the others).
7. **Glossary tooltip JS** (vanilla, no framework dependency) active on all editorial prose — landing + detail pages.

**Out of scope for 01.1** (remains with Phase 02):
- Methodology page (EDIT-03)
- Real chart-model builders for CHART-02/03/04
- Mobile-simplified heatmap fallback (CHART-04 specific)

</domain>

<decisions>
## Implementation Decisions

### Visual Redesign Target
- **D-01:** Reference aesthetic is **https://www.energydashboard.co.uk/live**. Replicate palette, typography, chart visual style, and dashboard/card layout pattern exactly. Placeholders acceptable for copy/assets where needed.
- **D-02:** **Rip out Pico CSS.** Replace with **Tailwind CSS** as the styling layer. The Phase 01 Pico + Okabe-Ito tokens in `01-UI-SPEC.md` are superseded for landing + detail pages.
- **D-03:** **Charting library is negotiable.** Reverse-engineer the library used by energydashboard.co.uk/live (inspect page source during research) and migrate to it. Observable Plot may be retained only if it can hit the target aesthetic convincingly. This overrides the CLAUDE.md stack recommendation for the interactive chart layer (Observable Framework as SSG stays).
- **D-04:** **Light theme only** carries forward from Phase 01. No dark-mode auto-switch.

### Landing Page Structure
- **D-05:** Layout is `hero shock counter → card grid (4 cards) → site footer`. No other sections on the landing page in Phase 01.1.
- **D-06:** **4 cards**, one per v1 chart defined in `docs/visualisation-scope.md`:
  1. CHART-01 "Scissors" — strike vs market (fully wired)
  2. CHART-02 "£/tCO₂ avoided" (placeholder)
  3. CHART-03 "Cumulative subsidy + Lorenz" (placeholder)
  4. CHART-04 "Daily generation heatmap" (placeholder)
- **D-07:** Each card shows: provocative title, one-line hook/caption, small visual affordance (thumbnail/sparkline — Claude's discretion on exact form), and is a clickable link to the detail page.
- **D-08:** Placeholder cards route to real detail pages with full editorial scaffolding (title, description, source citation, download buttons) but a placeholder chart body (e.g. "Coming in Phase 02" panel with the chart's intent described in prose).

### Shock Counter
- **D-09:** **Figure displayed:** cumulative consumer subsidy (£) for the **current calendar year to date**, computed at build time from the daily-ingested LCCC data. (YTD aligns with the Phase 01 UI-SPEC glossary and keeps the shock grounded in "this year".)
- **D-10:** **Count-up behaviour:** on page load, start the numeral at today's YTD value (NOT at zero), then **increment upward at a constant £/sec rate** indefinitely while the page is open. No reset, no cap during the session.
- **D-11:** **£/sec rate source:** derived from a rolling mean of recent daily subsidy (e.g. mean daily subsidy over the last ~30–90 days, converted to £/sec). The exact window and computation is Claude's discretion during planning — must be a single constant emitted by the build pipeline and read by the client JS.
- **D-12:** Accessibility: `prefers-reduced-motion: reduce` freezes the counter at today's YTD value (no animation). Numeral remains semantically a number for screen readers; the ticking animation is decorative.

### Chart Image Export (PNG)
- **D-13:** **One PNG per detail page**, downloaded via a plain `<a href="..." download="...">` button (no JS click handler). 44×44px min tap target.
- **D-14:** **Scissors chart:** a real, simplified static render (two-lines + area fill over "All rounds" aggregate — the OG-card aesthetic, not a per-round faithful reproduction). Generated by a new `pipeline/export_chart_images.py` module running inside the daily cron pipeline, so images refresh with the data.
- **D-15:** **Placeholder charts:** ship a placeholder PNG (same dimensions, "Chart coming in Phase 02" visual) so the download affordance exists on every detail page from day one.
- **D-16:** Image regen is a hard dependency on valid data artefacts — if schema validation fails in the daily pipeline, image regen is skipped and the previous PNG is retained (matches the existing "leave previous deployment intact" rule from OPS-02).

### Glossary Tooltip JS
- **D-17:** Vanilla-JS implementation, no framework dependency. Retain the Phase 01 UI-SPEC interaction contract: hover-150ms / tap / Esc / Enter-Space / `role="tooltip"` / `aria-describedby`.
- **D-18:** **Schema migration:** convert `src/content/glossary.json` from phrase keys (`"CfD"`, `"Strike price"`) to the `data-glossary` slug keys specified in Phase 01 UI-SPEC (`cfd`, `strike_price`, `reference_price`, `imrp`, `allocation_round`, `intermittent`, `dispatchable`). Breaking change is acceptable — there is no external consumer of the current schema.
- **D-19:** Add the two missing entries: `intermittent` and `dispatchable`. Copy to be written during planning.
- **D-20:** `<abbr data-glossary>` wrapping applies to **editorial prose on all pages** (landing + all 4 detail pages). Chart tick labels and axis titles do NOT receive the wrapper (keeps SVG clean). Plain Markdown in `*.md` pages is where the `<abbr>` markup lives.

### Routing
- **D-21:** Use Observable Framework's default **file-based routing**. Landing page at `src/index.md`; each chart at its own dedicated page (e.g. `src/charts/scissors.md` already exists — extend with `src/charts/co2-avoided.md`, etc.). Optimise for ease of scaling (one new file per future chart) and maintenance (one page per concept, no dynamic routes). Card links are plain `<a href="./charts/{slug}">`.

### Claude's Discretion
- Exact Tailwind integration path into Observable Framework (Framework has no first-class Tailwind story — pick between Tailwind CLI build step, PostCSS integration, or Tailwind CDN for the shortest path to ship; prefer a path that survives into Phase 02 without rework).
- Specific charting library once reverse-engineered from energydashboard.co.uk/live (do NOT assume — inspect first).
- Card thumbnail/sparkline form (static PNG, inline SVG, or CSS-only accent).
- Rolling-mean window for £/sec rate computation.
- Placeholder chart body visual (panel, blurred mock, icon grid — whatever matches the dashboard aesthetic).
- Where the Phase 01 scissors page assets (`src/charts/scissors.md`, `chart-3c.json.py`, `captions.json`) are preserved vs rewritten — preserve the data pipeline, rewrite the page shell to the new design.

### Folded Todos
None.

</decisions>

## Specific Ideas

- Reference aesthetic URL: **https://www.energydashboard.co.uk/live** — tone, density, and card pattern are the target.
